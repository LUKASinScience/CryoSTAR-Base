          ⚠
          Troubleshooting
          common WarpTools issues
          ▾
        

        

          


            
            

              

                White spots / bright artifacts in reconstructed tomograms
              

              

                Hot pixels that are not corrected by the gain reference appear as white spots spreading along the rotation axis in reconstructions.
                IMOD and RELION filter these automatically with thresholding; the WarpTools CLI does not.
                The solution is to create a defects file that masks these pixels.
              

              

                Root cause:
                Some cameras produce hot pixels that cannot be corrected by the gain reference.
                The CTF correction during reconstruction amplifies the ringing around them.
                Check your motion-corrected averages in warp_frameseries/average/ — hot pixels appear as single bright pixels.
              


              
              

                

                  Gain reference conventions
                  — multiplicative vs divisive
                  
                

                

                  

                    Type 1 — Multiplicative (most common): 
                    corrected = raw * gain. Gatan software has always produced this type.
                  

                  

                    Type 2 — Divisive (rare): 
                    corrected = raw / gain. Some early EPU EER data used this convention.
                  

                  

                    WarpTools assumes Type 1 (multiplicative) for all formats 
                    (.gain, .tif, .mrc).
                  

                  

                    Test: Apply gain to raw data. 
                    If hot pixels get worse, you likely have a Type 2 gain.
                    If hot pixels get better, it is the correct type.
                  

                  

                    Source: Dimitry Tegunov, Warp Google Groups (May 2026)
                  

                

              


              
              

                

                  Falcon 4 — tif2mrc conversion issue
                  
                

                

                  

                    Converting Falcon 4 .gain to .mrc with IMOD's tif2mrc 
                    can produce a gain that amplifies hot pixels instead of correcting them.
                    The defect may follow the gain flip orientation.
                  

                  
Fix — mask hot pixels in the gain reference itself:

                  
import mrcfile, numpy as np
with mrcfile.open('gainref.mrc') as mrc:
    gain = mrc.data.copy()
threshold = gain.mean() + 8 * gain.std()
gain[gain > threshold] = gain.mean()
with mrcfile.new('gainref_corrected.mrc', overwrite=True) as mrc:
    mrc.set_data(gain.astype(np.float32))

                  

                    Source: Luke Dillard, Warp Google Groups (May 2026)
                  

                

              


              
Step 1 — Create defects mask (Python)

              

                Masking above 8 standard deviations matches what IMOD does by default.
              

              
import mrcfile
import numpy as np

# Load a frame average where hot pixels are visible
frame = mrcfile.read('warp_frameseries/average/your_tomo_frame.mrc').astype(np.float64)

# Mask pixels above 8 standard deviations (matches IMOD default threshold)
frame = (frame - frame.mean()) / frame.std()
mask = (frame > 8) * 1.0

# Write defects file
mrcfile.write('defects.mrc', mask.astype(np.float16), overwrite=True)


              
Step 2 — Flip with IMOD (required due to gain/defects flip convention)

              
# Try flipx first, then flipy — use whichever removes the hot pixels in the averaged frames
clip flipx defects.mrc defects_flip.mrc


              
Step 3 — Add to create_settings

              
WarpTools create_settings ... --defects defects_flip.mrc

          Before Template Matching — Initial Model Workflow
          recommended first steps
        

        


          

            

              Why start with manual picking?
              Determine handedness, get a first reference, avoid template bias
              ▾
            

            

              

                Before running full template matching, hand-pick 50–200 particles from 1–3 representative tomograms.
                This gives you an unbiased initial reference and lets you determine the correct particle handedness —
                a wrong handedness produces mirror-image reconstructions and degrades TM accuracy significantly.
              

              

                

                  
Step 1 — Manual pick

                  
50–200 particles in 3dmod or Surforama. 1–3 tomograms is enough. Focus on clear, isolated particles.

                

                

                  
Step 2 — Initial Model

                  
In the RELION GUI: Jobs → Initial Model.
                    Runs relion_refine --denovo_3dref internally — unbiased 3D reference
                    without prior assumptions. Also available in Job Builder → RELION Initial Model.

                

                

                  
Step 3 — Check handedness

                  
Compare your map to a known reference (PDB / EMDB). Mirror with relion_image_handler --flip_z if needed.

                

              

            

          


          

            

              Refine before full TM
              3D classification → auto-refine → use as TM template
              ▾
            

            

              

                # 1. Manual picking → extract → RELION initial model

                # In RELION GUI: Jobs → Initial Model

                relion_refine --denovo_3dref --i manually_picked.star --o InitialModel/

                # 2. 3D classification — remove junk

                relion_refine --3dclass --i picked.star --ref InitialModel/model.mrc

                # 3. Auto-refinement — get best possible reference

                relion_refine --auto_refine --i class_good.star --ref class_good.mrc

                # 4. Use refined map as template for full PyTom TM
              

              

                This map is then used as the template in the Create Template job below.
                A good template dramatically improves TM sensitivity and specificity.

              What is missing-wedge bias?
              Why tilt near 0° or 180° produces false positives
              ▾
            

            

              

                The electron beam cannot tilt beyond ±60–70°, leaving a cone of Fourier space unmeasured — the missing wedge.
                Particles oriented along the beam axis are reconstructed with severe artefacts.
                Template Matching scores these highly because template and particle both have the same distortion — but they are false picks.
              

              

                
Artefact — tilt near 0° or 180°
Aligned along beam axis. Missing wedge covers most Fourier info. High TM score but false positive.

                
Real — tilt near 90°
Perpendicular to beam. Maximum Fourier coverage. Expected distribution for real particles.

              

            

          


          

            

              How to detect it
              Tilt angle distribution per class — junk shows >15% near-beam
              ▾
            

            

              

                Run Classification Analysis (below) → check tilt angle distribution per class.
                A junk class with >15% particles at tilt <20° or >160° is dominated by missing-wedge artefacts.
                Typically 5–10× enriched vs real class — more discriminative than LCC score alone.
              

            

          


          

            

              How to fix it — 4 strategies
              Filter, angular restriction, IsoNet, RELION tilt limit
              ▾
            

            

              

                
1 — Filter after classification
Exclude any class with >15% near-beam particles. Fastest fix.

                
2 — Angular search restriction in PyTom
Add --angular-search 45 or a tilt-angle mask excluding orientations within 20° of the beam axis.

                
3 — IsoNet2 — refinement only, NOT before TM
Fills the missing cone but suppresses real signal. Always run TM on raw tomograms. IsoNet for visualisation + refinement only.

                
4 — Tilt restriction in RELION
--restrict_tilt_angles in Refine3D. Consider --sigma_ang 5 in Round 2 to penalise large angular jumps.

              

            

          


          

            

              Pipeline integration
              LCC scores via star_score_matcher in STAR files
              ▾
            

            

              

                LCC scores are transferred by star_score_matcher_beta.py before RELION classification —
                your STAR files already contain _rlnLCCmax from the WarpTools → RELION workflow.
                The Classification Analysis tool reads these directly.

          LCC scores · CTF · tilt bias · spatial distribution

            The STAR file must contain _rlnLCCmax — this is the case when using
            the standard CryoSTAR-Base workflow (LCC transferred during WarpTools export step).

          M
          High-resolution multi-particle refinement — MTools / MCore
          Quick Start ↗
          MCore API ↗
        

        
        

          
          
          
        

        
        

          
          

            M jointly optimises particle poses, tilt-series alignments, CTF, and image deformations.
            The key trick: import your target protein and ribosomes together.
            Ribosomes are abundant, well-resolved, and their high particle count gives M strong signal to refine
            tilt-series geometry — which then improves your target protein too.
             Pyle et al. 2025 (V-ATPase, main ref) · Appel et al. 2026 (BCRII + ribosomes jointly) · Tegunov et al. Nat. Methods 2021
          

          
          

            

              1
              
RELION AutoRefine — get a starting map (even 20–30Å is enough to start M). Run ribosomes in parallel.

            

            

              2
              
Setup M — create Population → Source → Species for both target + ribosomes. Then run Sanity Check (iter=0) to verify setup.

            

            

              3
              
Round 1 — particle poses + 1×1 warp + defocus — start simple. Both species refine together. Ribosomes dominate alignment signal. Repeat until <0.2Å/round.

            

            

              4
              
Round 2+ — increase warp grid, add stage angles — 2×2 or 3×3 warp, then enable --refine_stageangles. See Grid schedule tab.

            

            

              5
              
CTF refinement — only after convergence — enable --ctf_defocus --ctf_astigmatism only after particle poses + warp + stage angles have converged. Appel 2026: CTF came in round 3+, after reaching ~5Å.

            

            

              6
              
Re-export → RELION → back to M — after M converges, re-export particles from improved tilt-series → RELION AutoRefine at higher resolution → return to M. Iterate until no more improvement.

            

          

          

            Do NOT add CTF refinement early. Appel et al. 2026: iterative particle pose + 3×3 warp + defocus → then + stage angles → then + CTF. Final round 6×6 + stage angles + CTF + poses → 7.9Å BCRII, 4.1Å ribosome.
          

        

        
        

          

            Based on Appel et al. 2026 (BCRII + ribosomes, 7.9Å / 4.1Å final) and M.md progressive strategy.
            Use both species throughout. Convergence = <0.2Å improvement per round.
          

          

            # Step 0 — Sanity Check (iter=0, no refinements)

            MCore --population m/project.population --perdevice_refine 4 --iter 0


            # Round 1 — particle poses + 1×1 warp + defocus. Repeat until converged.

            MCore --population m/project.population --refine_particleposes \

              --refine_imagewarp 1x1 --refine_defocus --perdevice_refine 4 --iter 3


            # Round 2 — 3×3 warp + stage angles + particle poses (Appel 2026)

            MCore --population m/project.population --refine_particleposes \

              --refine_imagewarp 3x3 --refine_stageangles --perdevice_refine 4 --iter 3


            # Round 3 — 3×3 warp + particle poses + CTF (only after convergence above)

            MCore --population m/project.population --refine_particleposes \

              --refine_imagewarp 3x3 --ctf_defocus --ctf_astigmatism --perdevice_refine 4 --iter 3


            # Final — 6×6 warp + stage angles + CTF + particle poses

            MCore --population m/project.population --refine_particleposes \

              --refine_imagewarp 6x6 --refine_stageangles --ctf_defocus --ctf_astigmatism --perdevice_refine 4 --iter 3
          

          

            After convergence at any stage: re-export particles → RELION AutoRefine at higher resolution → re-import to M.
            Appel 2026 re-exported and re-processed twice before the final M round.
          

          

            
Overfitting risk
Larger grids improve your species but may degrade field edges. Check microtubule subunits + membrane leaflets — not just your target resolution.

            
Volume warp
Only use --refine_volumewarp if particles are well distributed in all 3 spatial dimensions.

          

        

        
        

          

            
ts_template_match — new algorithm
Now uses MatchLargeVolume. Different scores vs dev36. Full tomo must fit in GPU memory.

            
ts_autolevel --patch_size in Å
Was pixels, now Ångström. Example: 128px × 11Å/px → --patch_size 1408

          

          

            ts_peak_align (new in dev37): align tilt series using correlation peaks from a particle STAR file.
            Lightweight alternative to M — no MCore setup. Does not improve CTF metadata.

IsoNet2
          Missing wedge correction · Denoising · CTF correction
          ↗ GitHub
        

        

          

            IsoNet2 is a self-supervised deep learning tool that simultaneously corrects the missing wedge, denoises, and corrects CTF in cryo-ET tomograms — achieving ~20 Å resolution without averaging. It has both a GUI and CLI.
          

          
          

            
Session Notes → Lab Notebook

            
            

              
              
            

          

          
          
          

            

              
              Detailed Workflow Guide
              Click to expand
            

            
            

              
              
              

                
Overview — Two Networks

                

                  IsoNet2 uses two sequential neural networks to enhance tomogram quality:
                

                

                  
Network 1 (NET1) — Denoising

                  
Removes noise from raw tomograms without deconvolution

                

                

                  
Network 2 (NET2) — Refinement

                  
Learns optimal reconstruction from denoised data

                

              


              
              

                
Requirements

                
    
                  
  • Even/odd tilt series (for CTF correction)
    • 
                  
  • GPU-enabled workstation
    • 
                  
  • 5-10 high-quality tomograms for training
    • 
                  
  • IsoNet2 environment activated
    • 
                

              


              
              

                

                  
1

                  
Prepare Data — Build Even/Odd Tomograms

                

                

                  
Build even/odd tomogram stacks from your best 5-10 tomograms.

                  

                    Parameters: Pixel size (check header), Voltage: 300 kV, Spherical aberration: 2.7 mm, Amplitude contrast: 0.1, Tilt range: adjust for your data
                  

                  

                    Defocus: rlnDefocus = mdoc_defocus × -10000
                  

                

              


              
              

                

                  
2

                  
Train Denoising Network (NET1)

                

                

                  
Train the network to remove noise from raw tomograms.

                  

                    Input:Raw even/odd tomograms
                    CTF mode:Network
                    GPU:Use available GPUs (0, 1 for multi-GPU systems)
                    CPUs:8-24 depending on workstation
                    Time:1-3 hours
                  

                

              


              
              

                

                  
3

                  
Predict Denoised Tomograms (NET1)

                

                

                  
Apply trained NET1 model to generate denoised tomograms.

                  

                    Model location: denoise/job#/*_full.pt (ignore epoch files)
                  

                  

                    Time: 1-2 minutes per tomogram
                  

                

              


              
              

                

                  
4

                  
Create Masks

                

                

                  
Generate binary or soft masks for refinement.

                  

                    Input:Denoised tomograms from NET1
                    Threshold:Standard deviation 80%
                  

                

              


              
              

                

                  
5

                  
Train Refinement Network (NET2)

                

                

                  
Learn optimal reconstruction from denoised data.

                  

                    Input:Denoised even/odd tomograms + masks
                    Sub-tomo size:128
                    Epochs:70
                    MW weight:200
                    B factor:200
                    CTF mode:Network
                    Time:10-20 hours
                  

                

              


              
              

                

                  
6

                  
Predict Refined Tomograms (NET2)

                

                

                  
Apply trained NET2 model for final reconstruction.

                  

                    Model location: refine/job#/*_full.pt
                  

                  

                    Time: 1-2 minutes per tomogram
                  

                

              


              
              

                
Using Pre-trained Models

                

                  Once you have trained models, process new tomograms without retraining:
                  
    
                    
  1. Create folder with new tomograms
    2. 
                    
  2. Run NET1 prediction with _full.pt from training
    3. 
                    
  3. Create masks from denoised output
    4. 
                    
  4. Run NET2 prediction with _full.pt from NET2 training
    5. 
                  

                  

                    Note: If you don't have even/odd data, use deconvolved tomograms as input
